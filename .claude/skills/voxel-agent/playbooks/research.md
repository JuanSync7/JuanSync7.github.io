# Research before adding detail

**Use when:** changing visual hierarchy, world scale, meshing or biome ecology.
**Inputs:** user observation, failed seed, current atlas, actual library source and inspected images.
**Outputs:** pinned reference card, observations, scoped implementation decision and comparison images.

1. Reproduce the current result. Record engine version and both public/layout seed namespaces.
2. Inspect source files, not only repository descriptions. Save exact paths, commit ids and content hashes in `docs/voxel-agent/references.json`; verify the pinned bytes match what was read.
3. View reference images before judging them. Record what they actually show; a filename is not evidence. Separate geology, ecological layers, place hierarchy, lighting and camera lessons.
4. Choose what fits this finite diorama. The current study uses noa's exact meshing/AO separation, Voxelize's deterministic stages, Luanti's constrained decorations and coherent noise fields. It does not import their engines, copy their code or bundle their assets.
5. Write the design defense before claiming quality: which observed fault does the change repair, which module owns it, and what visible/test evidence can reject it?
6. Render overview, close place, phone and neutral-orientation model sheets. Keep discoveries and unresolved weaknesses in the review record. A mechanical pass does not establish taste.

**Reject:** name-dropping a library without reading it; copied assets without explicit reuse scope; an unviewed screenshot described as inspected; making a larger catalog without realized diversity.
**Tools:** pinned repository reads, reference JSON, `voxel:gallery`, `voxel:browser`, agent image inspection.
